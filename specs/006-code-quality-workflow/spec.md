# Спецификация: правила стиля и обязательное ревью

**Ветка**: `003-niche-normalization`
**Дата**: 2026-10-30
**Статус**: согласовано в чате

## Согласованный объём и границы решения

После написания кода агент обязан проверить изменения отдельным скиллом ревью
по правилам проекта,
исправить замечания и выполнить автоматический gate перед сдачей работы.
Правила стиля находятся в одном проектном документе; остальные инструкции
ссылаются на него без копирования. Конституция проекта заполняется на основе
подтверждённых пользователем принципов. Изменения действуют в установленном
Spec Kit этого проекта и не переносятся в исходный пакет для новых проектов.

Продуктовая логика, API и DOM не меняются. Новые зависимости, коммиты, ветки,
публикация и внешние сервисы не входят в задачу.

## Сценарии и проверка

### Сценарий 1: следующий агент завершает изменение кода

После реализации агент обращается к правилам стиля, проводит ревью своего diff,
устраняет найденные проблемы и повторяет проверки. Он записывает реальные
результаты проверки и не объявляет работу завершённой с блокирующими замечаниями.

**Проверка**: действующие инструкции содержат обязательное ревью после
реализации и требуют записи результата и устранения замечаний до завершения.

### Сценарий 2: разработчик запускает gate

Одна команда последовательно проверяет типы, тесты и production-сборку.
Ненулевой код любого шага останавливает gate и возвращает ненулевой код всей
команды.

**Проверка**: `npm run check` завершается успешно на текущем проекте и
возвращает ошибку, если отдельная проверка падает.

## Требования

### Функциональные требования

- **FR-001**: Проектный style guide отражает согласованные сегодня предпочтения
  с примерами и границами применения, сохраняя KISS, DRY, YAGNI и понятность.
- **FR-002**: Проектные инструкции ссылаются на style guide без дублирования
  конкретных правил.
- **FR-003**: В `.agents/skills/` существует отдельный скилл ревью кода.
  Действующий шаг `speckit-implement` обязательно вызывает его после написания
  кода, до итогового отчёта и возможных Git-действий. Отдельная команда
  Spec Kit для ревью не создаётся.
- **FR-004**: Заполненная конституция формулирует устойчивые принципы процесса,
  порядок изменения правил и версию; подробный code style остаётся в guide.
- **FR-005**: `npm run check` запускает существующие проверки без новых пакетов.
- **FR-006**: Шаблон задач установленного пресета включает ревью и gate в
  критерии завершения следующих задач.
- **FR-007**: Настройки Spec Kit в исходном пакете для других проектов остаются
  нетронутыми.

## Критерии успеха

- **SC-001**: В проекте один документ с подробными правилами стиля; остальные
  постоянные инструкции ссылаются на него без повторения правил.
- **SC-002**: Отдельный скилл ревью обнаруживается в проекте; действующий путь
  завершения задачи требует его использования после кода, устранения находок
  и повторной проверки до отчёта.
- **SC-003**: Gate запускается одной командой и проверяет три существующих этапа.
- **SC-004**: Конституция не содержит шаблонных плейсхолдеров, имеет версию и
  согласуется с процессом Spec Kit.
- **SC-005**: Продуктовые тесты проходят, исходный пакет и Git-история не меняются.
