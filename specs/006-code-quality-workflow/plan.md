# План: правила стиля и обязательное ревью

**Ветка**: `003-niche-normalization` | **Дата**: 2026-10-30 |
**Спецификация**: [spec.md](./spec.md)

## Технический контекст

Next.js 16, TypeScript, Node test runner, npm и локально установленный Spec Kit
0.8.15. В проекте уже выполняются `npx tsc --noEmit`, Node-тесты и
`npm run build`. ESLint и Prettier не установлены. Существующие изменения
в рабочем дереве сохраняются; работа остаётся без коммита в текущей ветке.

## Проверка конституции

Конституция сейчас состоит из плейсхолдеров. Перед изменением правил процесса
заполнить её принципами, которые подтверждены сообщениями пользователя и
действующим `AGENTS.md`. Не добавлять продуктовых требований или неподтверждённых
правил. Сверить план и установленный шаблон задач с новой конституцией.

## Подход

1. Создать `docs/code-style.md` как единый источник подробных правил и примеров.
   Повторно используемые константы, деструктуризация, render-функции, Lodash,
   ошибки и фикстуры описать вместе с исключениями, чтобы не превращать стиль
   в механическое усложнение.
2. В `AGENTS.md` добавить короткую ссылку на guide и требование использовать
   обязательный шаг ревью; не копировать пункты style guide.
3. Заполнить `.specify/memory/constitution.md` устойчивыми принципами:
   согласованный объём, сохранение контрактов, проверяемость, поддерживаемость,
   обязательное ревью и управление изменениями. Использовать версию 1.0.0
   как первое принятие; приложить Sync Impact Report по инструкции Spec Kit.
4. Создать отдельный проектный скилл `.agents/skills/speckit-code-review/SKILL.md`.
   Он читает стиль и границы задачи, проверяет полный diff, фиксирует находки и
   результат повторной проверки. Это скилл, не новая команда Spec Kit.
   Обновить текущий пресет `.specify/presets/codex-code-workflow/commands/speckit.implement.md`
   и действующий `.agents/skills/speckit-implement/SKILL.md`: оба требуют
   выполнения нового скилла после кода и до завершения.
5. Добавить в установленный шаблон задач обязательный шаг ревью и gate,
   чтобы будущие `tasks.md` включали его явно.
6. Добавить npm scripts `typecheck`, `test`, `check`. `check` последовательно
   вызывает типы, тесты и сборку и останавливается при ошибке. Новые пакеты
   не ставить; `git diff --check` остаётся отдельной проверкой ревью.

## Проверка документации и конфигурации

Поведение продукта не меняется, поэтому тест Red → Green здесь был бы
искусственным. До правок зафиксировать отсутствие style guide, плейсхолдеры
конституции и отсутствие `check`. После правок проверить ссылки, отсутствие
плейсхолдеров и дублированных правил, совпадение установленного пресета с
действующим skill, валидировать отдельный skill, запустить `npm run check` и
`git diff --check`. Записать
каждый результат в `verification.md`.
