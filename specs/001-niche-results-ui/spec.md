# Feature Specification: Экран анализа ниши

**Feature Branch**: `001-niche-results-ui`  
**Created**: 2026-10-29  
**Status**: Согласовано  
**Input**: Верстка прототипа поиска публикаций Instagram с демонстрационным разбором ниши, таблицей реальных данных Apify, сортировкой и скачиванием JSON.

## Agreed scope and decision boundaries

Результат: один локальный экран для ввода описания ниши и просмотра демонстрационной выдачи. В объёме: ввод до 150 символов, настройки периода 1/3/7 дней, формата «Все / Только Reels / Только посты» и вручную вводимого лимита 1–50 сразу под полем, кнопка «Показать тренды» и последовательное появление разбора и таблицы до 50 публикаций из снимка Apify. «Посты» включают изображения и карусели. Выбор формата расположен рядом с периодом. До нажатия разбора и списка нет. После нажатия около секунды показывается загрузка разбора, затем появляется разбор и загрузка списка под ним, затем таблица с сортировкой по лайкам/комментариям/shares/дате, выбором нескольких слов из демонстрационного разбора по принципу «хотя бы одно» и скачиванием JSON. После второго этапа страница прокручивается к таблице; под разбором доступна ссылка на неё. По умолчанию — лайки по убыванию; дата — новые сначала. Декоративные номера убраны из заголовков и карточек тем; номера строк есть только в таблице. Вне объёма: вызовы модели, новый запуск Apify, серверная логика, авторизация и Docker.

При вводе произвольной ниши данные Apify не должны выдаваться за результаты нового поиска. Блок разбора и таблица явно помечены как демонстрационные данные из запроса «фитнес». Экспорт содержит текущие отображаемые записи и настройки интерфейса.

## User Scenarios & Testing

### User Story 1 — Задать параметры поиска (P1)

Пользователь описывает нишу обычными словами, видит счётчик символов и выбирает период, формат и длину списка.

**Independent Test**: Ввести текст длиной больше 150 символов; интерфейс не принимает символы сверх лимита. Изменить лимит на 1 и 50.

**Acceptance Scenarios**:

1. При открытии видны поле ввода, выбор периода и формата рядом с ним, а также поле для ручного ввода лимита 1–50.
   Вся видимая рамка лимита принимает клик и переводит фокус в поле; при фокусе текущее число выделяется для замены.
2. Под полем видны настройки выдачи и кнопка запуска. До нажатия блок разбора и таблица отсутствуют.
3. После нажатия при непустом тексте сначала виден индикатор загрузки разбора, затем пример разбора с меткой «демо» и индикатор загрузки списка ниже.
4. Кнопка подписана «Показать тренды»; после готовности данных пользователь видит таблицу благодаря прокрутке к ней и может перейти к ней по ссылке после разбора.

### User Story 2 — Изучить таблицу (P1)

После двух этапов демонстрационной загрузки пользователь видит снимок публикаций со ссылками, датой, форматом, метриками и совпавшими терминами.

**Independent Test**: Открыть страницу без ввода; таблицы нет. Ввести описание, нажать кнопку, дождаться двух этапов загрузки; затем первая запись имеет максимальное число лайков. Переключить сортировку на комментарии и shares.

**Acceptance Scenarios**:

1. При открытии таблица отсутствует.
2. После этапов загрузки записи упорядочены по лайкам по убыванию.
3. При выборе другой метрики или даты порядок меняется без повторного запуска.
4. Пользователь может отметить несколько слов из примера разбора галочками; остаются записи, у которых хотя бы одно выбранное слово есть в фактических `matchedTerms` Apify. Без выбранных слов видны все записи; выбор можно сбросить.
5. Для слова без совпадений показано пустое состояние без выдуманных результатов.
6. Число строк не превышает заданный пользователем лимит.
7. «Только Reels» оставляет записи `reel`, «Только посты» — записи `image` и `carousel`; «Все» показывает оба вида. Фильтр формата применяется до ограничения длины списка.
8. Единственные порядковые номера интерфейса — номера строк таблицы; они соответствуют текущему порядку после сортировки и фильтрации.

### User Story 3 — Скачать текущую выдачу (P2)

Пользователь скачивает JSON после таблицы.

**Independent Test**: Выбрать сортировку и лимит, скачать файл и проверить число и порядок записей.

**Acceptance Scenario**: Кнопка скачивания появляется вместе с таблицей; файл содержит именно видимые записи с URL, датой, форматом, метриками, основанием совпадения и настройками.

### Edge Cases

- Пустой ввод не создаёт иллюзию реального поиска.
- Неверный или пустой числовой лимит приводится к допустимому диапазону 1–50.
- Если для выбранного периода записей меньше лимита, показываются только имеющиеся записи.

## Requirements

### Functional Requirements

- **FR-001**: Ограничить ввод ниши 150 символами и показывать счётчик.
- **FR-002**: Показывать настройки выдачи непосредственно под полем и кнопку запуска после них; пример структурированного разбора ниши появляется после первого этапа загрузки.
- **FR-003**: Предоставить период 1/3/7 дней, выбор формата «Все / Только Reels / Только посты» рядом с ним и поле для ручного ввода числового лимита 1–50.
- **FR-004**: До нажатия кнопки не показывать разбор и таблицу; после нажатия с непустым описанием последовательно показывать загрузку разбора, разбор с загрузкой списка под ним, затем таблицу на снимке Apify из `Mox`.
- **FR-005**: Сортировать видимые записи по лайкам, комментариям, shares или дате по убыванию (для даты — новые сначала), по умолчанию по лайкам.
- **FR-006**: После появления таблицы скачать JSON с текущими видимыми записями и настройками.
- **FR-007**: Явно отделять демонстрационные данные от будущего живого поиска.
- **FR-008**: В готовом списке предоставить фильтр с галочками по нескольким словам из демонстрационного разбора, включая слова без совпадений; применять объединение по «ИЛИ» к `matchedTerms` Apify, показывать все записи при пустом выборе и пустое состояние при нуле совпадений.
- **FR-009**: Применять выбор формата к фактическому `contentType` снимка: `reel` для Reels, `image` и `carousel` для постов, затем ограничивать число строк. Включать формат в экспортируемые настройки.
- **FR-010**: Подписать кнопку «Показать тренды»; после второго этапа автоматически показать таблицу прокруткой к ней и оставить ссылку перехода под разбором. Убрать декоративную нумерацию вне таблицы, добавить в таблицу номера видимых строк.
- **FR-011**: Вся видимая область поля лимита должна переводить фокус в редактируемый ввод; при фокусе текущее число выделяется, чтобы пользователь мог сразу набрать другое. При выходе из поля значение приводится к 1–50.

### Key Entities

- **Публикация**: URL, формат, подпись, автор, дата, лайки, комментарии, shares, совпавшие термины и способ нахождения.
- **Настройки выдачи**: период, формат, лимит, критерий сортировки и массив выбранных ключевых слов.
- **Пример формализации**: исходная фраза, темы, языки и поисковые термины; статический мок.

## Success Criteria

### Measurable Outcomes

- **SC-001**: До запуска видны только ввод, настройки и кнопка; после двух этапов загрузки доступны разбор и таблица без вызова внешних сервисов.
- **SC-002**: Для каждой сортировки значения выбранной метрики идут по невозрастанию.
- **SC-003**: Экспортируемое число записей равно числу строк таблицы.
- **SC-004**: Страница собирается командой `npm run build`.
- **SC-005**: Выбор слова без совпадений показывает ноль записей, не подменяя фильтр или данные.

## Assumptions

- Период в демо считается относительно времени завершённого запуска Apify, поэтому снимок не «стареет» при повторном открытии страницы.
- Таблица использует только опубликованные URL и метрики; временные URL медиа из выгрузки не сохраняются.
