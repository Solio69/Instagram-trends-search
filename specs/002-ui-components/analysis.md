## Технические границы

- Текущий экран содержит всё состояние и JSX в `app/page.tsx`; разбиение не требует изменения чистых функций `demo-flow.ts` и `results.ts`.
- Next.js локально документирует поддержку `.module.scss` после установки `sass`, а `use client` требуется на границе интерактивного дерева. Следовательно, серверная `page.tsx` может собирать статическую оболочку и `TrendExplorer`.
- Снимок Apify и пример формализации остаются в `Mox`; новый API и дополнительные данные не нужны.
- CSS сейчас глобален и содержит общие `table`, `th`, `td`, `textarea`. Перенос в локальные модули устраняет возможные коллизии.
- Исправление поля лимита зависит от семантики связанного `<label>`; при переносе нужно сохранить её вместе с выделением числа на фокусе.
- В `.specify/memory/constitution.md` остаются шаблонные поля. Из них не выводятся новые правила.

## Найденное противоречие и повторная проверка

Изначально FR-005 запрещал новые зависимости, хотя пользователь выбрал SCSS и локальная документация требует `sass`. Требование уточнено: допускается только dev-пакет `sass`. После отдельного read-only прохода по `spec.md`, `plan.md`, `tasks.md` и `research.md` противоречий не осталось.

## Решение

Можно реализовывать. Сначала фиксируется успешный базовый прогон 11 тестов и сборки, затем выносятся компоненты и SCSS, после чего те же проверки повторяются. Проверку поведения браузера отмечать отдельно; если доступ к UI ограничен, не считать её успешной.

## Уточнения структуры

Пользователь отдельно закрепил папку и `index.ts` для каждого компонента, а также локальное хранение его типов и констант. После обновления `spec.md`, `plan.md`, `tasks.md` и `checklist.md` выполнен read-only проход по FR-008, T003–T004, CHK010–CHK011 и плану импортов. Эти требования согласованы: `app/constants` содержит только общие варианты и метаданные, подписи и props-типы владельца находятся в его папке. Блокирующих противоречий нет.

Пользователь уточнил, что последние «общие константы» означают цвета и шрифты SCSS, а повторяющиеся стили должны быть миксинами; договорённость о локальных текстах и типах остаётся. После обновления FR-009, плана и CHK012 отдельный read-only проход показал согласованную структуру `_tokens.scss` и `_mixins.scss`. Блокирующих противоречий нет.

## Уточнение по повторяющейся разметке и типам props

Пользователь привёл три числовые ячейки строки таблицы как пример повторяющихся элементов и попросил строить такие группы из массива через отдельную функцию рендера. Также уточнил, что типы props должны находиться прямо в файле компонента. Общий массив метрик может обслуживать строку и заголовки таблицы; другие однородные группы — сводку, темы, слова и варианты переключателя. Существующее поведение не меняется, дополнительная зависимость не нужна. После изменения FR-008 и добавления FR-010 противоречий с планом нет.
