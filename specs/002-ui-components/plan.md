# Implementation Plan: Компонентная структура UI

**Branch**: `002-ui-components` | **Date**: 2026-10-29 | **Spec**: [spec.md](./spec.md)

## Summary

Оставить в `app/page.tsx` только композицию страницы. Клиентское состояние, таймеры и экспорт разместить в `TrendExplorer`; форму, разбор и результаты вынести в компоненты. Переиспользуемые элементы формы получают props и не знают о демоданных. Стили компонентов перенести в локальные `.module.scss` с БЭМ-именованием и вложенностью `&`; глобальные правила оставить только для токенов и базовых элементов. Данные и поведение не менять.

## Technical Context

**Stack**: Next.js 16.4.3, React 19.3.1, TypeScript 7, SCSS Modules  
**Data**: `Mox/*.json`  
**Tests**: `node --experimental-strip-types --test tests/demo-flow.test.mjs tests/results.test.mjs`; `npm run build`  
**Dependencies**: установить только dev-пакет `sass`; текущая локальная документация Next.js требует его для `.module.scss`.

## Constitution Check

Конституция остаётся шаблоном. Действуют `AGENTS.md` и согласованный объём. Новые правила не выводятся из шаблона.

## Design

- `app/page.tsx`: серверная композиция оболочки и интерактивного блока.
- `app/components/TrendExplorer/`: клиентское состояние, эффекты, экспорт, `index.ts`.
- `app/components/ui/<Component>/`: `NicheInput`, `SegmentedControl`, `ResultLimitField`, `ActionButton`, `LoadingStatus`; у каждого собственные TSX, SCSS и `index.ts`.
- `app/components/formalization/<Component>/`: панель, сводный элемент, карточка темы; каждый компонент в своей папке.
- `app/components/results/<Component>/`: секция результатов, фильтр слов, таблица и строка; каждый компонент в своей папке.
- `app/components/layout/<Component>/`: шапка, hero и подвал; каждый компонент в своей папке.
- Папки компонентов: типы props прямо в файлах `.tsx`, `constants.ts` для собственных подписей при необходимости.
- `app/constants/`: только общие варианты выбора, подписи метрик и метаданные демоданных.
- `app/globals.scss`: только токены и базовые правила.
- `app/components/**/*.module.scss`: локальные стили компонентов; БЭМ и вложенность `&`.
- `app/styles/_tokens.scss`: общие цвета и шрифты; `app/styles/_mixins.scss`: повторяющиеся правила.

Граница `use client` находится в `TrendExplorer`; импортированные им дочерние компоненты работают внутри этой границы. Серверная страница не получает обработчики событий. Props фиксируют контракты компонентов. Подписи хранятся в `constants.ts` соответствующего компонента, если они локальны; общие варианты — в `app/constants`. Сами публикации остаются в JSON.

Повторяющаяся разметка строится из данных: общий массив числовых метрик задаёт порядок ячеек и заголовков таблицы; отдельные функции рендера оформляют эти элементы, пункты сводки, темы, ключевые слова и варианты сегментированных переключателей. Типы props находятся рядом с соответствующими функциями компонентов в `.tsx`.

## Test-first and verification plan

Рефакторинг без изменения поведения опирается на существующие тесты функций: прогнать их до и после переноса. Новый контракт универсальной кнопки `type="submit"` проверить сборкой TypeScript и точечной сверкой props; тест, повторяющий JSX, не добавлять. Удаление двух плашек проверить в собранном HTML. Границы компонент, `index.ts` и БЭМ-структуру проверить по файлам и импортам; поиск цветовых литералов вне `_tokens.scss` и общих шрифтов — отдельно. Сборка должна подтвердить компиляцию SCSS Modules. Браузерная проверка формы, этапов, таблицы и экспорта желательна; при недоступном UI записать Blocked, не выдавая статический анализ за клик.
