# Feature Specification: Компонентная структура UI

**Feature Branch**: `002-ui-components`  
**Created**: 2026-10-29  
**Status**: Согласовано  
**Input**: Вынести текущий экран из одной страницы в переиспользуемые UI-компоненты, разнести строковые константы и убрать две плашки.

## Agreed scope and decision boundaries

Результат: `app/page.tsx` собирает статическую оболочку и клиентский экран; ввод ниши, сегментированные переключатели, поле лимита, универсальная кнопка, разбор запроса, фильтр ключевых слов и таблица выделены в небольшие типизированные компоненты. Каждый компонент находится в своей папке с `index.ts` для импорта и локальным `.module.scss`. Строки интерфейса и настройки демонстрационного источника хранятся отдельно от JSX. Классы названы по БЭМ, вложенность выражена через `&`. Плашки «Локальный прототип» и «Свободная формулировка» удалены.

Текущие данные `Mox`, два этапа загрузки, фильтрация, сортировка, числовой лимит, экспорт и маркировка демо сохраняются. Исправление клика по всей рамке лимита должно остаться. Допускается только dev-зависимость `sass`, необходимая для SCSS. Вне объёма: новая дизайн-система, другие пакеты, API, серверная логика и изменение бизнес-правил.

## User Scenarios & Testing

### User Story 1 — Ввести запрос и параметры (P1)

Пользователь вводит нишу, выбирает срок и формат, вручную заменяет число публикаций, нажимает «Показать тренды».

**Acceptance Scenarios**:

1. Ввод ограничен 150 символами; период, формат и лимит работают как прежде.
2. Клик по любой части поля лимита фокусирует ввод; число выделяется для замены.
3. После нажатия сначала появляется пример разбора, затем таблица.
4. Плашек «Локальный прототип» и «Свободная формулировка» нет.

### User Story 2 — Изучить и скачать результаты (P1)

Пользователь меняет сортировку, отмечает несколько ключевых слов, видит до 50 записей и скачивает JSON.

**Acceptance Scenarios**:

1. Срок, формат, несколько слов по «ИЛИ», сортировка и лимит дают прежние результаты.
2. Разбор состоит из отдельных элементов для сводки и темы; таблица — из строки публикации и отдельного фильтра ключевых слов.
3. Кнопка скачивания сохраняет именно текущие строки и настройки.

## Requirements

- **FR-001**: Вынести ввод ниши, сегментированный переключатель, лимит и универсальную кнопку в переиспользуемые типизированные компоненты. Кнопка поддерживает `type="submit"` без изменения своего кода.
- **FR-002**: Вынести блок разбора, его сводные элементы и карточки тем в отдельные компоненты.
- **FR-003**: Вынести фильтр ключевых слов и блок результатов с таблицей в отдельные компоненты.
- **FR-004**: Вынести строковые подписи, варианты переключателей и метаданные снимка из JSX в отдельные модули.
- **FR-005**: Сохранить поведение существующих чистых функций и клиентских состояний; не добавлять новые зависимости, кроме необходимого для SCSS dev-пакета `sass`.
- **FR-006**: Удалить две названные плашки из интерфейса.
- **FR-007**: Перенести стили компонентов в `.module.scss` рядом с ними, использовать БЭМ-классы и вложенность `&`; оставить в глобальных стилях только базовые правила и токены.
- **FR-008**: Для каждого компонента создать отдельную папку с `index.ts`; импорты компонентов направлять на эту папку, не на файл реализации. Типы пропсов описывать прямо в файле компонента, локальные константы хранить в его папке; универсальные константы — в `app/constants`.
- **FR-009**: Все цвета и шрифты хранить в общих SCSS-токенах; повторяющиеся стилистические блоки оформлять общими миксинами. Не оставлять цветовые литералы в файлах компонентов.
- **FR-010**: Повторяющиеся элементы UI рендерить из массивов через отдельные функции рендера, включая числовые ячейки строк таблицы и соответствующие заголовки; порядок и поведение сохранить.

## Success Criteria

- `app/page.tsx` не содержит состояния формы, JSX таблицы или длинных текстов интерфейса.
- Все существующие тесты проходят, `npm run build` успешна.
- Статический HTML не содержит двух удалённых плашек; проверка в браузере выполняется при доступности инструмента.

## Assumptions

- «Блок сбора» означает существующий блок разбора запроса; пользователь подтвердил это.
- Работа остаётся без коммита и push. Ветка задачи — `002-ui-components`.
