# Кодревью: активный разбор ниши

| Принцип | Наблюдение | Решение |
|---|---|---|
| KISS, поддерживаемость | В `TrendExplorer` статус, результат и ошибка хранились в отдельных состояниях. Это допускало внутренне противоречивые сочетания при будущих изменениях. | Объединены в один тип состояний `idle/loading/ready/error`; счётчик версии запроса сохранён. |
| SOLID | Модуль разбора отвечает за OpenRouter и проверку данных, Route Handler — за HTTP. Это разумная граница для текущего размера приложения. | Граница сохранена; коды ошибки типизированы, а отображение в HTTP-статусы находится в маршруте. |
| KISS, YAGNI | Функции рендера для одного `map` и массив из двух фиксированных сводных строк добавляли переходы по коду без переиспользования. | Разметка встроена в компоненты с прежним порядком и содержимым. |
| DRY | Одинаковое запасное сообщение об ошибке в клиенте повторялось. | Вынесено в одну локальную константу. |
| DRY, границы модулей | Ограничение в 150 символов повторяется на клиентской и серверной границе. | Оставлено: общий модуль ради одного числа усложнил бы текущий прототип; обе границы независимо защищены. |

## Отложенные замечания

- Демо-компоненты списка публикаций связаны с `DEMO_FORMALIZATION` и `DEMO_SOURCE`. При подключении реального источника стоит передавать данные через props и отделить тип публикации от JSON-снимка. Сейчас они не используются в рабочем пути и не менялись.
- Промпт просит 2–6 слов на группу, а проверка ответа принимает 1–8. Это существующее расхождение между инструкцией модели и допустимым ответом. Выравнивание изменит правила приёма данных, поэтому требует отдельного решения.
- Для роста нагрузки позже понадобятся решения по лимитам запросов, повторным попыткам и контролю расходов OpenRouter. Они меняют поведение; в этот рефакторинг не включены.

Новые зависимости, глобальное состояние, кэш и дополнительные слои абстракции не добавлены.
