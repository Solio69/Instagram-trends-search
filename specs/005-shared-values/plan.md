# План: общие значения и тестовые данные

**Ветка**: `003-niche-normalization` | **Дата**: 2026-10-30 | **Спецификация**: [spec.md](./spec.md)

## Стек и ограничения

Next.js 16.4.3, React 19.3.1, TypeScript 7, Node test runner, `lodash` и `@types/lodash` по отдельному запросу пользователя. Изменения затрагивают `app/`, `tests/` и зависимости; существующие незакоммиченные изменения сохраняются. Конституция проекта содержит шаблонные заполнители; действуют `AGENTS.md` и эта согласованная задача.

## Реализация

1. Разместить общие значения статусов и текста ошибки в `app/constants/niche-request.ts`, коды нормализации — рядом с модулем нормализации, значения фильтров и метрик — рядом с `app/lib/results.ts`. Потребители импортируют константы вместо строк.
2. Выделить общий JSON-заголовок запроса и общий заголовок `no-store` ответа, сохранив существующие варианты ответов.
3. Деструктурировать статические наборы `COPY` в модулях компонентов; индексируемый по динамическому `stage` набор оставить индексируемым.
4. Перенести мок ответа модели и массив публикаций в `tests/fixtures/`. Проверки ожидаемого поведения и контракта оставить в тестах.
5. Для конечных наборов форматов использовать типизированные таблицы значений. Деструктурировать `data` в `FormalizationPanel`, `topic` в `TopicCard` и `KeywordFilter`, статические классы в `Hero` и странице. Простые бинарные проверки оставить на месте.
6. Общие атрибуты внешних ссылок держать в `app/constants/links.ts`; локальные подписи источника и разделитель совпавших слов — рядом с `PostRow`. Сохранить поведение для неизвестного `discoveryType`.
7. В `ResultsSection` вычислять `visibleCount` из `posts.length` в начале компонента и использовать в трёх местах без изменения условий.
8. Общие HTTP-статусы, сообщения ошибок API, повторяющиеся строковые и числовые значения, роли модели и атрибуты HTML/ARIA вынести в константы с сохранением текущих значений. Для `HTTP_METHOD.POST` и полей `NICHE_API_FIELD` использовать прямой доступ без промежуточных алиасов.
9. Использовать Lodash для проверок типа; сохранить отклонение объектных строк и точные условия приёма объектов, массивов и чисел. Для TypeScript предоставить локальные type guards там, где типы Lodash не сужают `unknown`.
10. Деструктурировать `status` запроса в `SearchPanel` и вычислять `isReady`/`isError` до JSX; вынести JSX-отрисовку темы, термина, пустой строки таблицы и трёх состояний панели поиска в render-функции.
11. В `ResultLimitField` назвать регулярное выражение допустимых цифр и извлекать введённое значение один раз в обработчике.
