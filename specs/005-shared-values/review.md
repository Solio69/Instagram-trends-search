# Итоговое ревью

- Повторяющиеся доменные значения объединены: статусы запроса, коды ошибок, фильтры, форматы, метрики, этап загрузки и варианты кнопки. Совпадающий текст запасной ошибки, JSON-заголовок запроса и `no-store` имеют общие источники.
- Статические наборы `COPY` деструктурированы на уровне модуля; `LOADING_COPY[stage]` и отображения по выбранной метрике остаются динамическими.
- Данные моков ответа модели и публикаций вынесены в `tests/fixtures/`. Ожидания тестов на HTTP-коды, ошибки и сортировку не заменены константами реализации, чтобы тесты продолжали проверять контракт.
- По последующим замечаниям пользователя типы кнопок и полей, повторяемые атрибуты HTML/ARIA, роли, пустая строка, пробел, ключи JSON-схемы, числовые лимиты и настройки модели вынесены в константы. Коды ответов API и сообщения ошибок используют общие источники.
- Для прямого импорта TypeScript в Node test runner добавлено `allowImportingTsExtensions` при существующем `noEmit`; production-сборка проверена.
- Последующие замечания ревью учтены: длинные цепочки выбора формата заменены таблицами, `data` и `topic` деструктурированы, статические CSS-классы в `Hero` и `page` вынесены на уровень модуля. Настройки двух внешних ссылок объединены; `PostRow` использует именованные подписи и разделитель.
- Повторное `posts.length` в `ResultsSection` заменено локальным `visibleCount` без изменения условия отключения кнопки.
- Проверки объектов, строк, массивов и конечных чисел используют Lodash; локальный type guard сохраняет отклонение объектных строк. `HTTP_METHOD.POST` и `NICHE_API_FIELD` применяются напрямую, без алиасов.
- В `SearchPanel` вычислены `isReady` и `isError`; состояния панели, элементы темы и термина и пустая строка таблицы вынесены в render-функции без изменения DOM. Регулярное выражение в `ResultLimitField` вынесено из обработчика.
